# Tester avec un lecteur d'écran

Ce guide teste les composants du socle avec un lecteur d'écran, comme le fait un audit RGAA. Les tests automatiques vérifient les rôles et les noms (axe, dans trois moteurs). Ils ne vérifient pas ce qu'un lecteur d'écran annonce, ni l'ordre de ses annonces.

Aucun de ces tests n'a encore été fait : la colonne « État » le dit.

## Prérequis

- Storybook, lancé par `npm run storybook`, ou sa version construite.
- Au moins deux des combinaisons suivantes, celles de la plupart des usagers :

## 1. Préparez chaque test

1. Ouvrez la story du composant seule : `iframe.html?id=<id>&viewMode=story`.
2. Démarrez le lecteur d'écran, avec ses réglages par défaut.
3. Placez le focus avant le composant, en haut de la page.

## 2. Testez

1. Parcourez le composant au clavier seul : Tab, les flèches, Entrée, Espace, Échap.
2. Notez ce que le lecteur d'écran annonce à chaque touche.
3. Comparez avec l'annonce attendue du tableau de la section 3.
4. Parcourez-le aussi en mode lecture, avec les flèches du lecteur d'écran.

Les mots des annonces varient selon le lecteur d'écran et sa langue. Comparez le sens, pas les mots.

## 4. Notez les résultats

1. Remplacez « À faire » par la combinaison testée et son résultat : « NVDA et Firefox : conforme ».
2. Pour un écart, ouvrez une issue avec le geste, l'annonce entendue et l'annonce attendue.
3. Une règle d'usage vérifiée à la main garde `checkedBy: manual` dans son document DSDS.
