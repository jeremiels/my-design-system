# Contrôleurs et état

Un composant composite sépare trois couches ([ADR 0010](?path=/docs/documentation-adr-0010-état-contrôleurs-et-mixins--docs)) :

<table>
  <thead>
    <tr>
      <th>Couche</th>
      <th>Emplacement</th>
      <th>Contenu</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>État</td>
      <td>`packages/components/src/state/`</td>
      <td>Des fonctions pures, sans DOM ni Lit, testées dans Node</td>
    </tr>
    <tr>
      <td>Connexion</td>
      <td>`packages/components/src/controllers/`</td>
      <td>Des reactive controllers de Lit : le DOM, l'ARIA, les événements</td>
    </tr>
    <tr>
      <td>Composant</td>
      <td>`packages/components/src/components/`</td>
      <td>Les propriétés publiques, le rendu, les styles</td>
    </tr>
  </tbody>
</table>

- Un contrôleur est un objet que le composant crée. Il n'ajoute ni propriété ni attribut au composant.
- Un comportement qui a une API publique est un mixin : voir [Mixins](?path=/docs/documentation-référence-mixins--docs).
- `@unicorne/components` exporte les contrôleurs, leurs feuilles et les fonctions d'état. Les marques les utilisent dans leurs propres composants.

```ts
import {
  AnchoredPopoverController,
  anchoredPopoverStyles,
  DSBaseElement,
} from "@unicorne/components";

export class AcmeMenu extends DSBaseElement {
  static styles = [DSBaseElement.styles ?? [], anchoredPopoverStyles, acmeMenuStyles];

  #popover = new AnchoredPopoverController(this);
}
```

- Créez un contrôleur dans un champ de la classe, ou dans son constructeur.
- Un contrôleur n'adopte aucune feuille. Ajoutez la feuille qu'il exporte à `static styles`.
- Un contrôleur n'apparaît pas dans le manifest. Le composant déclare les membres `protected` qu'une marque surcharge, et les passe au contrôleur.

## CommandsController

Permet à un composant de recevoir des commandes : d'un `<button commandfor command>` natif, ou d'un composant avec `withInvoker`. `Modal` le crée.

```ts
export class AcmeDrawer extends DSBaseElement {
  constructor() {
    super();
    new CommandsController(this, (event) => this.handleCommand(event));
  }

  protected handleCommand(event: CommandEvent) {
    if (event.command === "--toggle-drawer") {
      this.open = !this.open;
    }
  }
}
```

- Le second argument reçoit chaque commande : `event.command` est son nom, `event.source` le bouton.
- Nommez les commandes d'un composant avec le préfixe `--`. Le navigateur n'envoie jamais une commande intégrée (`show-modal`) à un custom element.
- Ignorez les commandes inconnues : le polyfill envoie aussi les commandes intégrées.
- Là où Invoker Commands manquent, le premier composant connecté charge le polyfill. Les boutons natifs de la page en ont besoin.

## AnchoredPopoverController

Affiche un popover du shadow root dans le top layer, ancré sous un autre élément du même shadow root : la liste d'un autocomplete, un menu, une infobulle. `ComboboxBase` le crée.

<table>
  <thead>
    <tr>
      <th>Membre</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`open(popover, ancre)`</td>
      <td>
        Affiche `popover` dans le top layer, sous `ancre`. La promesse se résout une fois le popover
        affiché et positionné.
      </td>
    </tr>
    <tr>
      <td>`close(popover)`</td>
      <td>Masque `popover` tout de suite</td>
    </tr>
    <tr>
      <td>`isOpen(popover)`</td>
      <td>Dit si `popover` est ouvert</td>
    </tr>
    <tr>
      <td>`anchoredPopoverStyles`</td>
      <td>La feuille du contrôleur, exportée à part : le composant l'ajoute à `static styles`</td>
    </tr>
  </tbody>
</table>

```ts
export class AcmeMenu extends DSBaseElement {
  static styles = [DSBaseElement.styles ?? [], anchoredPopoverStyles, acmeMenuStyles];

  #popover = new AnchoredPopoverController(this);

  render() {
    return html`
      <button id="trigger" type="button" @click=${this.#toggle}>Actions</button>
      <div class="menu" popover="manual"><slot></slot></div>
    `;
  }

  #toggle = () => {
    const menu = this.renderRoot.querySelector<HTMLElement>(".menu")!;
    const trigger = this.renderRoot.querySelector<HTMLElement>("#trigger")!;
    if (this.#popover.isOpen(menu)) {
      this.#popover.close(menu);
    } else {
      void this.#popover.open(menu, trigger);
    }
  };
}
```

- Chaque `[popover]` du shadow root est un `popover="manual"` ancré. Le composant décide de sa fermeture : Escape, un clic à l'extérieur, un choix. `DismissController` détecte les trois premiers.
- Le contrôleur pose `data-open` sur le popover ouvert, dans tous les navigateurs. La feuille du composant écrit l'état ouvert sur `[data-open]`, pas sur `:popover-open`.
- Un popover fermé est masqué par `display: none !important`. Ni le `display` du composant ni un `::part()` de marque ne l'affichent.
- Le popover se place sous son ancre, aligné sur son bord de début, au moins aussi large. Il se retourne au-dessus quand il déborderait du viewport.
- Sa marge de bloc est l'espace entre l'ancre et lui.
- Le contrôleur ferme les popovers qu'il a ouverts quand le composant quitte le document.
- Le contrôleur ne fournit aucun token : la feuille du composant peint le popover.

## ListboxController

Le contrôleur relie la liste au DOM. Il ne tient aucun état : le composant lui donne les options et l'index de l'option active.

- `aria-activedescendant` ne vise qu'un élément de son arbre ([ADR 0007](?path=/docs/documentation-adr-0007-champs-de-formulaire--docs)). La liste rend donc ses propres copies des options, dans le shadow root du contrôle.
- Le contrôleur lit les enfants `<option>` et suit leurs changements. Il ne les modifie jamais : un framework continue de les rendre.
- Un hôte rendu par un serveur lit ses enfants après son premier rendu. Ce rendu est alors celui du serveur ([ADR 0014](?path=/docs/documentation-adr-0014-vue-et-rendu-serveur--docs)).
- Un appui du pointeur sur la liste garde le focus sur le contrôle.
- La liste défile jusqu'à l'option active quand son index change.

- La ligne de `status()` reste visible en bas de la liste qui défile. Elle est masquée aux technologies d'assistance : annoncez son texte par une live region.
- Les tokens `--u-listbox-*` viennent de `@unicorne/tokens` (`src/component/listbox/`). Le composant les documente avec `@tokens listbox`.

## RovingFocusController

Donne un tabindex mobile aux éléments d'un composant composite : Tab atteint un élément, les flèches déplacent le focus vers les autres. `RadioGroup`, `Tabs`, `Toolbar` et `Menu` le créent.

    <tr>
      <td>`activeIndex()`</td>
      <td>

        activé.
      </td>
    </tr>
    <tr>
      <td>`axis()`</td>
      <td>Les flèches qui déplacent le focus : `vertical`, `horizontal` ou `both`</td>
    </tr>
    <tr>
      <td>`homeEnd`</td>
      <td>Home et End vont au premier et au dernier élément</td>
    </tr>
    <tr>
      <td>`moved(index)`</td>
      <td>Appelé une fois le focus déplacé par le clavier : un groupe de radios coche l'élément</td>
    </tr>
    <tr>
      <td>`isDisabled(élément)`</td>
      <td>
        Optionnel : dit si l'utilisateur n'atteint pas l'élément. Par défaut, `:disabled` ou
        `aria-disabled="true"`.
      </td>
    </tr>
  </tbody>

- Le contrôleur pose le `tabindex` des éléments après chaque rendu de l'hôte : 0 pour l'élément que Tab atteint, -1 pour les autres.
- Rendez l'hôte de nouveau quand ses éléments changent, au `slotchange` de son slot.
- Un déplacement boucle aux extrémités, saute les éléments désactivés et suit le sens du texte (`state/collection.ts`).
- L'élément d'une touche est le plus proche de sa cible : les éléments peuvent s'imbriquer, comme dans un arbre.
- Une touche avec Alt, Ctrl ou Meta reste à la page.

## DismissController

Ferme un popup de son hôte, et dit pourquoi : Échap, un appui hors de l'hôte, le focus qui le quitte. `ComboboxBase` le crée, pour Échap et le focus.

<table>
  <thead>
    <tr>
      <th>Option du constructeur</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`active(reason)`</td>
      <td>Dit si cette cause ferme maintenant : le popup est ouvert, par exemple</td>
    </tr>
    <tr>
      <td>`dismiss(reason)`</td>
      <td>Ferme le popup. `reason` vaut `escape-key`, `outside-press` ou `focus-out`.</td>
    </tr>
    <tr>
      <td>`escapeKey`</td>
      <td>Échap dans l'hôte ferme</td>
    </tr>
    <tr>
      <td>`outsidePress`</td>
      <td>Un appui hors de l'hôte ferme</td>
    </tr>
    <tr>
      <td>`focusOut`</td>
      <td>Le focus qui quitte l'hôte ferme</td>
    </tr>
  </tbody>
</table>

```ts
export class AcmeMenu extends DSBaseElement {
  constructor() {
    super();
    new DismissController(this, {
      active: () => this.open,
      dismiss: (reason) => this.hide(reason),
      escapeKey: true,
      outsidePress: true,
      focusOut: true,
    });
  }
}
```

- Le composant choisit les causes, et transmet `reason` à son événement ([API des composants](?path=/docs/documentation-référence-api-des-composants--docs), section 5).
- Le contrôleur empêche l'action par défaut d'Échap et arrête sa propagation : une modale autour de l'hôte reste ouverte.
- Échap ne ferme rien pendant qu'une méthode de saisie compose le texte.
- Un appui hors de l'hôte descend et remonte hors de lui. Une sélection de texte qui finit dehors ne ferme rien.
- Le chemin de l'événement traverse les shadow roots. Un popup du shadow root, dans le top layer, est dans l'hôte.
- Le focus qui passe à un enfant de l'hôte ne le quitte pas.
- Un appui dehors qui déplace le focus ferme tout de suite, avec la cause `outside-press`, et non `focus-out`.
- Une modale n'en a pas besoin : le navigateur ferme le `<dialog>`, et seul le `<dialog>` reçoit un appui sur son `::backdrop`.

## HoverIntentController

Montre un popup tant que le pointeur reste sur son hôte, ou que le focus du clavier y est. `Tooltip` le crée.

<table>
  <thead>
    <tr>
      <th>Option du constructeur</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`show(reason)`</td>
      <td>Montre le popup : `hover` ou `focus-in`</td>
    </tr>
    <tr>
      <td>`hide()`</td>
      <td>Cache le popup : le pointeur est parti</td>
    </tr>
    <tr>
      <td>`showDelay`, `hideDelay`</td>
      <td>Les délais, en millisecondes : 300 et 100 par défaut</td>
    </tr>
  </tbody>
</table>

- Un passage bref du pointeur ne montre rien.
- Le pointeur va du déclencheur au popup sans le cacher : le popup descend de l'hôte.
- Le focus du clavier (`:focus-visible`) montre tout de suite, pas un clic.
- Le focus qui part est le rôle de `DismissController`.

## OverflowController

Dit si le contenu d'un conteneur qui défile dépasse son début ou sa fin, et le fait défiler. `Tabs` le crée, pour ses boutons de défilement, et `Table`, pour sa zone qui défile.

- Le constructeur reçoit l'hôte et une fonction qui donne le conteneur.
- `start` et `end` disent si du contenu dépasse le début ou la fin, dans le sens du texte.
- `scroll("start" | "end")` fait défiler le conteneur de la plus grande part de sa largeur.
- `scrolls` dit si le conteneur défile, sur l'un ou l'autre axe. `Table` rend alors sa zone focalisable.
- Le contrôleur mesure après chaque rendu de l'hôte, à chaque changement de taille (`ResizeObserver`) et à chaque défilement. Il rend l'hôte de nouveau quand une mesure change.

## DirectionController

Lit la direction du texte de son hôte à sa connexion : `:dir()` manque à la [matrice](?path=/docs/documentation-référence-support-navigateurs--docs). `Calendar`, `Pagination`, `Tabs`, `BreadcrumbItem` et `TreeItem` le créent, pour leurs chevrons ([ADR 0032](?path=/docs/documentation-adr-0032-bouton-bascule-divulgation-et-chevrons--docs)).

- Le constructeur reçoit l'hôte.
- `rtl` dit si le texte va de droite à gauche.
- `side("start" | "end")` donne le côté physique, `left` ou `right` : `chevron-${side("end")}`.
- Le contrôleur rend l'hôte de nouveau quand la direction change à une connexion. Le premier rendu, sur un serveur aussi, va de gauche à droite.
- Une touche fléchée lit la direction au moment de l'appui : `calendar` et `tree` la lisent dans leur gestionnaire de clavier.

## LoadController

Charge des données pour son hôte, d'un serveur par exemple, un chargement à la fois ([ADR 0026](?path=/docs/documentation-adr-0026-grandes-listes-et-options-chargées--docs)). `EditableComboboxBase` le crée, pour `loadOptions`.

    <tr>

      <td>Annule le chargement et oublie `value`</td>
    </tr>
    <tr>

- `value` garde l'ancienne réponse jusqu'à la nouvelle.
- Une tâche rejetée vide `value`. Son erreur atteint les gestionnaires d'erreurs de la page (`reportError()`).
- L'hôte se rend de nouveau à chaque changement de `pending`, `loading`, `slow` et `value`.
- La déconnexion de l'hôte annule le chargement.

## AnnounceController

Rend une live region dans le shadow root de son hôte. Les technologies d'assistance lisent ce que reçoit `announce()`, sans que le focus bouge : le nombre de suggestions, une page chargée, un message enregistré. `ComboboxBase` le crée.

      <td>

        d'écran, pour une erreur qui ne peut pas attendre.

      <td>`render()`</td>
      <td>Rend la région</td>
    </tr>
    <tr>
      <td>`announce(message)`</td>
      <td>
        Annonce `message` au prochain rendu de l'hôte. `""` vide la région, sans rien annoncer.
      </td>
    </tr>
    <tr>

      <td>Le dernier message annoncé, `""` sans message</td>
    </tr>
    <tr>

- Rendez la région dès le premier rendu. Une région ajoutée avec son texte n'est pas annoncée.
- Le même message, deux fois de suite, est annoncé deux fois : le contrôleur change le texte de la région.
- La région se vide quand l'hôte quitte le document.
- `ComboboxBase` annonce chaque nouveau `popupStatus`, le nombre de suggestions d'`autocomplete` par exemple.

## Sortie animée

Trois fonctions animent la sortie d'un élément du top layer, un `<dialog>` ou un popover, dans toute la matrice. `Modal` et `ComboboxBase` les appellent. Ce ne sont pas des contrôleurs : elles ne tiennent aucun état d'un composant.

<table>
  <thead>
    <tr>
      <th>Fonction</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`closeWithTransition(élément, fermer)`</td>
      <td>
        Appelle `fermer` (`dialog.close()`, `hidePopover()`) à la fin de la transition de sortie de
        l'élément
      </td>
    </tr>
    <tr>
      <td>`cancelExitTransition(élément)`</td>
      <td>Arrête une sortie en cours : l'élément reste ouvert</td>
    </tr>
    <tr>
      <td>`isClosing(élément)`</td>
      <td>Dit si l'élément est en sortie</td>
    </tr>
  </tbody>
</table>

La feuille du composant écrit la transition :

```css
dialog {
  opacity: 0;
  transition-property: opacity, display, overlay;
  transition-duration: var(--u-modal-transition-duration);
  transition-behavior: allow-discrete;
}
dialog[open]:where(:not([data-closing])) {
  opacity: 1;
}
@starting-style {
  dialog[open]:where(:not([data-closing])) {
    opacity: 0;
  }
}
```

- L'état fermé est sur l'élément. L'état ouvert est sur `[open]`, `:popover-open` ou le `[data-open]` d'`AnchoredPopoverController`, suivi de `:where(:not([data-closing]))`.
- L'entrée part de l'état fermé, écrit dans `@starting-style`.
- `display` et `overlay` sont dans `transition-property`, avec `transition-behavior: allow-discrete` dans sa propre déclaration.
- `closeWithTransition()` attend les animations finies de l'élément et de son `::backdrop`, pas celles de son contenu. Elle attend 2 secondes au plus.
- Sans transition, en mouvement réduit par exemple, l'élément se ferme tout de suite.

### Support navigateurs

- Chrome et Edge 117 ont `overlay` : la fonction ferme l'élément tout de suite, et le CSS anime la sortie.
- Firefox et Safari n'ont pas `overlay`. La fonction pose `data-closing` : l'élément rejoint son état fermé dans le top layer, puis se ferme.
- Sans `@starting-style` (Chrome avant 117, Firefox avant 129, Safari avant 17.5), l'entrée est instantanée.

## État d'une collection

`packages/components/src/state/collection.ts` calcule l'élément actif d'une collection : les options d'une liste, les membres d'un composant composite (radios, onglets, éléments de menu).

<table>
  <thead>
    <tr>
      <th>Fonction</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`moveIndex(éléments, index, déplacement)`</td>
      <td>
        L'index de l'élément actif après un déplacement : `next`, `previous`, `first`, `last` ou
        `none`
      </td>
    </tr>
    <tr>
      <td>`enabledIndexes(éléments)`</td>
      <td>Les index des éléments activés</td>
    </tr>
    <tr>
      <td>`collectionKeyMove(touche, { axis, direction, homeEnd })`</td>
      <td>Le déplacement d'une touche, `undefined` pour une touche qui ne déplace rien</td>
    </tr>
  </tbody>
</table>

- Un déplacement boucle aux extrémités et saute les éléments désactivés.
- Sans élément activé, aucun élément n'est actif : l'index vaut -1.
- `axis` choisit les flèches : ArrowDown et ArrowUp pour `vertical`, ArrowRight et ArrowLeft pour `horizontal`, les quatre pour `both`.
- `direction` vaut `ltr` par défaut. En `rtl`, ArrowLeft va à l'élément suivant.
- `homeEnd` fait de Home et End des déplacements. Il vaut `false` par défaut : dans un input, ces touches déplacent le curseur.

## Recherche par saisie

`packages/components/src/state/typeahead.ts` trouve l'élément dont le libellé commence par le texte tapé. `Select` et `Menu` l'utilisent.

<table>
  <thead>
    <tr>
      <th>Membre</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`typeahead(état, touche, instant, éléments, index)`</td>
      <td>
        Ajoute la touche au texte tapé, et renvoie le nouvel état et l'index de l'élément trouvé, -1
        sans élément
      </td>
    </tr>
    <tr>
      <td>`isTypeaheadKey(événement, état, instant)`</td>
      <td>Dit si une touche tape un caractère pour la recherche</td>
    </tr>
    <tr>
      <td>`emptyTypeahead`</td>
      <td>L'état sans texte tapé</td>
    </tr>
    <tr>
      <td>`normalizeText(texte)`</td>
      <td>Le texte sans casse ni accents. Le filtre d'`autocomplete` l'utilise aussi.</td>
    </tr>
  </tbody>
</table>

- Le texte tapé dure 500 ms (`TYPEAHEAD_DELAY`) après chaque touche.
- Un seul caractère cherche après l'élément actif, en bouclant. Le même caractère tapé de nouveau passe à l'élément suivant qui commence par lui.
- Les éléments désactivés sont sautés.
- Espace continue un texte tapé. Seule, elle reste au composant : elle choisit l'élément actif.

## Sélection

`packages/components/src/state/selection.ts` tient les valeurs choisies parmi des éléments. `Select` l'utilise avec `multiple`, `Table` avec `selectable`.

- `toggleValue(éléments, valeurs, valeur)` choisit la valeur, ou la retire, dans l'ordre des éléments. Un élément désactivé ne change rien : le même tableau revient.
- `orderedValues(éléments, valeurs)` range les valeurs dans l'ordre des éléments, sans les valeurs inconnues.
- `toggleAll(éléments, valeurs)` choisit tous les éléments activés, ou aucun quand ils le sont tous. Les éléments désactivés gardent leur choix.

## Dates d'un calendrier

`packages/components/src/state/calendar.ts` calcule les dates de `calendar` et de `date-picker`. Une date est `{ year, month, day }`, sans heure ni fuseau horaire.

- `parseDate(texte)` et `formatDate(date)` lisent et écrivent le format de HTML, `YYYY-MM-DD`. Une date impossible donne `undefined`.
- `addDays()` et `addMonths()` déplacent une date. Un mois plus court donne son dernier jour.
- `isWithin()` et `clampDate()` tiennent une date entre `min` et `max`.
- `monthWeeks(année, mois, premierJour)` donne les semaines d'un mois. Un jour d'un mois voisin vaut `undefined`.
- `calendarKeyMove(touche, date, options)` donne la date d'une touche de la grille, dans le sens du texte.

## Nœuds d'un arbre

`packages/components/src/state/tree.ts` donne les nœuds d'un arbre. `Tree` lit ses éléments comme des nœuds `{ expanded, children }`.

- `visibleNodes(racines)` donne les nœuds visibles, dans l'ordre : les racines, et les enfants des nœuds ouverts.
- `parentOf(racines, nœud)` donne le parent d'un nœud, `undefined` pour une racine.

## Tri d'un tableau

`packages/components/src/state/table.ts` tient le tri d'un tableau ([ADR 0030](?path=/docs/documentation-adr-0030-tableau--docs)). `Table` montre le tri ; l'application trie ses lignes.

- `nextSort(tri, clé)` donne le tri après un appui sur l'en-tête de la colonne `clé` : l'autre sens sur la colonne qui trie, croissant sur une autre.
- `sortRows(lignes, tri, langue)` renvoie une copie des lignes triées : les objets de l'application, que ses `table-row` montrent. Les nombres et les dates se comparent comme tels, le texte dans l'ordre de la langue, avec ses nombres. Les valeurs vides vont à la fin, dans les deux sens.

## File des toasts

`packages/components/src/state/toast.ts` tient les messages d'un `toaster`, le plus récent à la fin.

- `addToast(file, message, max)` ajoute un message avec l'id suivant. Au-delà de `max`, les plus anciens partent : `dropped` les donne.
- `removeToast(file, id)` retire un message. La même file revient pour un id inconnu.
- `emptyToastQueue` est la file vide.
