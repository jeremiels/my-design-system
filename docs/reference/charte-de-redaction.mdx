# Charte de rédaction

Cette charte s'applique à toute la documentation du socle : les pages de Storybook (`docs/`), `AGENTS.md` et les skills (`.claude/skills/`). Un humain lit la documentation vite. Un agent la charge sans être surchargé. Aucune information périmée ne reste cachée dans une page.

## Trois règles

1. **Un type par page** (Diátaxis).
2. **Des phrases courtes, avec un seul sens** (principes d'ASD-STE100).
3. **Le présent seulement.**

- Une page qui mélange deux types devient deux pages liées.
- Un skill est un guide pour les agents. Il contient la procédure et les conventions qui n'existent nulle part ailleurs.
- `AGENTS.md` est un index. Il renvoie vers les skills et les pages.

## Des phrases courtes, avec un seul sens

Ces règles reprennent les principes de la langue contrôlée ASD-STE100, appliqués au français.

- Écrivez une idée par phrase.
- Limitez une phrase à 25 mots, et une étape de procédure à 20 mots.
- Écrivez une action par étape, à l'impératif, avec « vous » : « Lancez `npm run example`. »
- Écrivez à la voix active : « Le plugin compile l'import. »
- Utilisez un mot pour un sens, celui du glossaire. N'utilisez pas de synonyme pour varier le style.
- Supprimez le remplissage : pas de section « Avantages » ni « Conclusion », pas d'adjectif promotionnel (« puissant », « moderne »).
- Présentez des faits parallèles en liste ou en tableau.

## Le présent seulement

La documentation décrit le système tel qu'il est.

- N'utilisez ni le futur ni le passé. Évitez « sera », « désormais », « nouveau », « ne… plus ».
- L'historique et les plans vont dans les ADR et dans l'historique git.
- Une échéance fixée est un fait du présent : « Mozilla maintient Firefox ESR 115 jusqu'en mars 2027. »
- N'écrivez pas de fait qui vieillit seul, comme la dernière version d'un navigateur.

## Une source par fait

- Chaque règle vit dans une seule page. Les autres pages et les skills mettent un lien vers elle.
- La JSDoc est la source de l'API des composants. Storybook l'affiche, et les pages ne la recopient pas.
- Le document DSDS d'un composant (`<nom>.dsds.yaml`) est la source de ses règles d'usage. Storybook les affiche dans la page du composant. Ce format est un pilote, limité à `button` et `button-link`.
- Un fait exact dans le code (un fichier, une commande) se cite par son chemin.

## Langue

- Les pages, `AGENTS.md` et les skills sont en français.
- Le code, ses commentaires, la JSDoc et les messages de commit sont en anglais.
- Les noms d'API restent tels quels : `part`, `slot`, `:host`, `defineComponents()`.
