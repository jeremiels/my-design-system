# Support navigateurs

Le socle supporte les canaux étendus des entreprises (Firefox ESR, Chrome et Edge Extended Stable). Il supporte aussi Android et iOS, y compris le Safari des iPhone bloqués sur iOS 16.

## Règle

- **Public :** le plancher d'un moteur est la plus ancienne version que le public utilise encore.
- **Exclusion :** un plancher plus haut que le public est une décision. La matrice donne la part exclue et le coût de l'inclure.
- **Architecture :** les composants associés aux formulaires demandent `ElementInternals` et les feuilles de style constructibles. Ce minimum ne descend pas sans changer d'architecture.
- **Fonctionnalités :** une fonctionnalité suit le plancher et ne le fixe jamais. Absente du plancher, elle s'utilise en amélioration progressive ou avec une valeur de repli.
- **Parts :** elles viennent de `caniuse-lite` (StatCounter), pour la France, en novembre 2026. Elles couvrent tous les sites, robots compris. Les statistiques de l'application grand public les remplacent quand elles existent.

- **Source de vérité :** le champ `"browserslist"` de `package.json`. Il alimente `build.target` (JS), `build.cssTarget` (CSS, abaissé par Lightning CSS) et `npm run compat`.
- **Noms Android :** dans `browserslist`, `chrome` et `firefox` désignent les versions de bureau. Android a ses propres noms : `and_chr`, `and_ff`, `samsung` et `op_mob`.
- **Une version récente seulement :** les données de `browserslist` ne connaissent qu'une version récente de `and_chr`, `and_ff` et `op_mob`. caniuse ne mesure donc pas leur public exclu. Le plancher de leur moteur est vérifié par `chrome >= 111` et `firefox >= 115`.
- **Versions figées :** la matrice nomme des versions, pas une requête glissante comme `baseline widely available`. Elle change seulement par une décision.

## Fonctionnalités à surveiller

<table>
  <thead>
    <tr>
      <th>Fonctionnalité</th>
      <th>Règle</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Nesting CSS</td>
      <td>
        Autorisé dans les sources : Lightning CSS l'aplatit au build. Le serveur de développement ne
        l'abaisse pas.
      </td>
    </tr>
    <tr>
      <td>CSS module scripts</td>
      <td>
        Jamais livrés : le plugin `packages/components/plugins/css-import-attributes.ts` les
        compile. Le build échoue s'il reste un import `.css` dans le JS produit.
      </td>
    </tr>
    <tr>
      <td>`:state()`</td>
      <td>
        Amélioration progressive : `customStates` est sans effet sur Chrome 90–124, Firefox avant
        126 et Safari avant 17.4. Un état nécessaire au rendu se reflète aussi en attribut.
      </td>
    </tr>
    <tr>
      <td>`::backdrop`</td>
      <td>
        N'hérite de rien avant Chrome 122, Firefox 120 et Safari 17.4. Une valeur de repli littérale
        y est tolérée.
      </td>
    </tr>
    <tr>
      <td>`light-dark()`</td>
      <td>
        Non utilisé : absent avant Chrome 123, Firefox 120 et Safari 17.5. Le thème sombre passe par
        `prefers-color-scheme` et `data-theme`, et `color-scheme` suit les mêmes déclencheurs.
      </td>
    </tr>
    <tr>
      <td>`text-wrap`, `interpolate-size`</td>
      <td>Amélioration progressive, `interpolate-size` sous `@supports`</td>
    </tr>
    <tr>
      <td>Invoker Commands (`commandfor`, `command`)</td>
      <td>
        Natifs depuis Chrome et Edge 135, Firefox 144 et Safari 26.2. Ailleurs, `withInvoker` et
        `withCommands` chargent `invokers-polyfill` à la demande ([ADR
        0008](?path=/docs/documentation-adr-0008-commandes-et-modale--docs)).
      </td>
    </tr>
    <tr>
      <td>Popover API (`popover`, `showPopover()`)</td>
      <td>
        Depuis Chrome et Edge 114, Firefox 125 et Safari 17. Ailleurs, `withAnchoredPopover` fixe le
        popover au-dessus de la page, hors du top layer ([ADR
        0009](?path=/docs/documentation-adr-0009-autocomplete-combobox-et-popovers-ancrés--docs)).
      </td>
    </tr>
    <tr>
      <td>CSS anchor positioning (`position-area`, `position-try-fallbacks`, `anchor-size()`)</td>
      <td>
        Depuis Chrome et Edge 129, Firefox 147 et Safari 26. Ailleurs, `withAnchoredPopover` charge
        Floating UI à la demande ([ADR
        0009](?path=/docs/documentation-adr-0009-autocomplete-combobox-et-popovers-ancrés--docs)).
      </td>
    </tr>
    <tr>
      <td>`@starting-style`, `transition-behavior`, `overlay`</td>
      <td>
        Amélioration progressive. Avant Chrome 117, Firefox 129 et Safari 17.5, l'entrée est
        instantanée. Sans `overlay` (Firefox, Safari), `withExitTransition` retarde la
        fermeture.
      </td>
    </tr>
    <tr>
      <td>`closedby` de `<dialog>`</td>
      <td>
        Depuis Chrome et Edge 134 et Firefox 141, absent de Safari. `modal` y gère elle-même le clic
        extérieur et `closedby="none"`.
      </td>
    </tr>
  </tbody>
</table>

Toute autre fonctionnalité récente se vérifie contre la matrice (MDN, caniuse) avant usage.

## Vérifications

<table>
  <thead>
    <tr>
      <th>Commande</th>
      <th>Ce qu'elle vérifie</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`npm run compat`</td>
      <td>
        Syntaxe JS de `dist/` (`es-check`) et fonctionnalités CSS des sources (`doiuse`), contre la
        matrice
      </td>
    </tr>
    <tr>
      <td>`npx vitest run`</td>
      <td>
        Stories et tests, dans les versions récentes de Chromium, Firefox et WebKit (Playwright)
      </td>
    </tr>
    <tr>
      <td>`npm run example`</td>
      <td>Le `dist/` livré, consommé par la marque ACME, dans une version récente de Chromium</td>
    </tr>
  </tbody>
</table>

- `doiuse` ne connaît que les données de caniuse. Il ne détecte ni `text-wrap`, ni l'héritage de `::backdrop`, ni `:state()`, ni les at-rules imbriquées.
- Les constats de `doiuse` acceptés sont listés avec leur raison dans `IGNORED` (`scripts/check-css-compat.mjs`).
- Aucun test automatique ne couvre les versions minimales : Vitest et `npm run example` utilisent les navigateurs récents de Playwright. Seul `npm run compat` vérifie la matrice.
- Aucun test automatique ne tourne sur Android : Vitest teste Chromium et Firefox dans leurs versions de bureau. Samsung Internet n'est testé nulle part.
