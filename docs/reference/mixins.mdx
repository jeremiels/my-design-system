# Mixins

Un mixin ajoute à une classe de composant un comportement qui a une API publique : une propriété, un attribut, une méthode. Le socle exporte trois mixins : `withDisabled`, `withInternals` et `withInvoker`. Les marques les appliquent à leurs propres composants.

Un comportement sans API publique est un contrôleur : voir [Contrôleurs et état](?path=/docs/documentation-référence-contrôleurs-et-état--docs). La raison de ce partage est dans l'[ADR 0010](?path=/docs/documentation-adr-0010-état-contrôleurs-et-mixins--docs).

```ts
import { DSBaseElement, withDisabled, withInternals } from "@unicorne/components";

export class AcmeField extends withInternals(withDisabled(DSBaseElement)) {
  static formAssociated = true;
}
```

- Appliquez un mixin directement dans `extends`, jamais par une constante : l'analyseur du manifest ne suit que l'héritage écrit en ligne.
- Un mixin garde les propriétés, les méthodes et les styles de la classe de base.

## withDisabled

Désactive un composant.

<table>
  <thead>
    <tr>
      <th>Membre</th>
      <th>Accès</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`disabled`</td>
      <td>public, attribut reflété</td>
      <td>Désactive le composant. Valeur par défaut : `false`.</td>
    </tr>
    <tr>
      <td>`isDisabled`</td>
      <td>`protected`, lecture seule</td>
      <td>
        `true` si `disabled` est vrai, ou si un `<fieldset disabled>` ancêtre désactive un composant
        associé à un formulaire
      </td>
    </tr>
  </tbody>
</table>

- L'hôte d'un composant désactivé porte `aria-disabled="true"`.
- `:host([disabled])` et `:host(:disabled)` reçoivent `pointer-events: none` et `opacity: var(--u-opacity-disabled)`.
- Le composant rend son template et ignore les interactions à partir de `isDisabled`, pas de `disabled`.
- Un composant associé à un formulaire (`static formAssociated = true`) est désactivé par un `<fieldset disabled>` ancêtre, sans attribut. Le navigateur appelle alors `formDisabledCallback()`, que le mixin implémente.

## withInternals

Attache les `ElementInternals` du composant.

<table>
  <thead>
    <tr>
      <th>Membre</th>
      <th>Accès</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`internals`</td>
      <td>`protected`</td>
      <td>
        Les `ElementInternals` du composant, attachés dans le constructeur. `undefined` seulement
        dans une émulation du DOM sans `attachInternals()`.
      </td>
    </tr>
    <tr>
      <td>`customStates`</td>
      <td>`protected`</td>
      <td>
        `set(nom, actif)` et `has(nom)` : activent et lisent les états `:state(nom)` du composant.
        `FieldBase` active `user-invalid` pendant qu'une erreur s'affiche
      </td>
    </tr>
  </tbody>
</table>

- Appliquez `withInternals` seulement à un composant qui en a besoin :
  - il participe à un formulaire (`internals.form`, `setFormValue()`, validité) ;
  - il expose des états `:state()` ;
  - il définit son rôle ARIA par `internals.role`.
- `attachInternals()` fonctionne une fois par élément. N'appelez jamais `this.attachInternals()` dans une classe qui a ce mixin.
- N'appliquez pas le mixin à une classe qui l'a déjà, comme `Button`.
- Une seconde attache lève l'erreur `NotSupportedError` du navigateur, et le composant ne se construit pas. Le mixin laisse passer cette erreur.
- `internals` et `customStates` sont `protected` : ils donnent le contrôle complet de la valeur de formulaire, de la validité et de l'ARIA. Ils restent réservés au composant et à ses sous-classes.

### Support navigateurs

`customStates` est sans effet là où `:state()` standard n'existe pas : Chrome 90–124, Firefox avant 126 et Safari avant 17.4. Ces versions sont dans la [matrice](?path=/docs/documentation-référence-support-navigateurs--docs). Un état nécessaire au rendu se reflète donc aussi en attribut. Un champ affiche son erreur sans `:state(user-invalid)`.

## withInvoker

Fait d'un composant qui rend un `<button>` natif un bouton de commande, comme `<button commandfor command>` (Invoker Commands). `Button` l'applique.

<table>
  <thead>
    <tr>
      <th>Membre</th>
      <th>Accès</th>
      <th>Description</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`commandFor`</td>
      <td>public, attribut `commandfor`</td>
      <td>L'`id` de l'élément contrôlé, dans l'arbre du composant : le document, ou son shadow root</td>
    </tr>
    <tr>
      <td>`command`</td>
      <td>public, attribut `command`</td>
      <td>
        La commande envoyée au clic : une commande intégrée pour un `<dialog>` ou un popover natif
        (`show-modal`, `toggle-popover`), ou une commande `--` pour un composant (`--show-modal`)
      </td>
    </tr>
    <tr>
      <td>`commandForElement`</td>
      <td>public, propriété seulement</td>
      <td>
        L'élément contrôlé. Prioritaire sur `commandfor`, il atteint un élément d'un shadow root
        englobant.
      </td>
    </tr>
    <tr>
      <td>`invokerControl`</td>
      <td>`protected`, lecture seule</td>
      <td>
        Le `<button>` natif qui envoie la commande : le premier `button` du shadow root. Surchargez-le
        si le template en rend un autre avant.
      </td>
    </tr>
  </tbody>
</table>

- Le mixin passe la commande et sa cible au `<button>` natif, après chaque rendu et à chaque clic.
- Le navigateur envoie la commande. `event.source` désigne l'hôte du composant, pas son bouton interne.
- Une commande intégrée vers un `<dialog>` ou un popover natif fonctionne : `command="show-modal"` ouvre un `<dialog>`.
- Un composant désactivé n'envoie rien : son `<button>` natif est `disabled`.
- N'appliquez pas le mixin à un lien (`ButtonLink`) : seul un `<button>` envoie une commande.

### Support navigateurs

Invoker Commands existent depuis Chrome et Edge 135, Firefox 144 et Safari 26.2.

- Ailleurs, le premier composant qui a une `command` charge `invokers-polyfill` avec `import()`.
- Le polyfill ignore une cible située dans un shadow root autre que le document. Le mixin envoie alors lui-même la commande `--`.
- Le mixin n'assigne `commandForElement` au bouton qu'après le chargement du polyfill. Une propriété assignée avant masquerait celle du polyfill.
