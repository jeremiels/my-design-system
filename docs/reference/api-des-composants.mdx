# API des composants

Ces règles s'appliquent à chaque composant du socle et des marques. Elles fixent les noms et les formes de l'API publique.

- Une règle qui commence par « De préférence » est un défaut : une revue peut la discuter. Les autres sont des règles.
- Avant d'ajouter un nom, cherchez-le dans cette page, puis dans `packages/components/custom-elements.json`.
- La JSDoc reste la source de l'API de chaque composant (skill `component-api-docs`).
- Le partage de l'API avec Figma est décidé dans l'[ADR 0016](?path=/docs/documentation-adr-0016-api-partagée-entre-le-code-et-figma--docs).

- Un nom en minuscules dans Figma est un nom du code, à l'identique.
- Un nom qui commence par une majuscule est propre à Figma. Le code n'a aucun nom de cette forme.
- Un élément partagé a le même nom, les mêmes valeurs et la même valeur par défaut des deux côtés.
- Un attribut lié à un modifier de tokens est partagé : `variant` et `size` de `button`, `variant` d'`alert` (`packages/components/terrazzo.config.ts`).
- Un trait d'un document DSDS est partagé. Le document donne le sens de chaque valeur.
- Un élément du code absent de Figma est propre au code.
- Une propriété sans effet visible, que le designer décide pour chaque instance, est partagée. Exemple : le `label` d'une icône qui porte un sens.
- Figma porte une telle propriété par une propriété de texte, liée à un calque masqué `metadata`, à la racine du composant.

- Un booléen Figma montre ou masque un calque, rien d'autre. Un booléen qui change plusieurs calques est donc une variante.

- La correspondance d'un composant vit dans `<nom>.figma.ts`, un gabarit Code Connect à côté de sa classe. Il écrit le HTML d'une instance Figma.
- `<nom>.figma.ts` change dans la même PR que l'API du composant.
- Un élément partagé se crée, se renomme ou se retire par une PR. Le fichier Figma suit après le merge.

## 3. Noms

### Balises

- La balise est `<préfixe>-<nom>`. Le nom est en anglais, en kebab-case.
- Un composant prend le nom du motif APG qu'il réalise (`autocomplete`, `modal`), ou de l'élément natif qu'il remplace (`textarea`).
- Un champ rend un libellé et un contrôle : il étend `FieldBase` et se nomme `<sorte>-field` (`text-field`). Un nom natif ou APG passe avant cette règle.
- Un composant qui mène à une autre page est un lien : `<nom>-link` (`button-link`).
- Un groupe est un composant, nommé `<membre>-group` : `radio-group` contient des `radio`.

### Attributs et propriétés

- Un attribut est en anglais, en minuscules, en kebab-case : `error-message`. Sa propriété porte le même nom en camelCase : `errorMessage`.
- Un attribut copié de HTML garde l'orthographe de HTML : `minlength`, `closedby`, `commandfor`. Sa propriété garde celle du DOM : `minLength`, `readOnly`.
- Un attribut est un nom ou un adjectif, sans `is`, `has` ni `should` : `open`, `disabled`, `required`, comme en HTML.
- Une propriété sans attribut porte une valeur riche : un tableau, un objet ou une fonction (`options`, `resultsMessage`).

### Booléens

- Un booléen vaut `false` par défaut. Il nomme le cas qui n'est pas le défaut : `disabled`, jamais `enabled`.
- Un attribut booléen présent vaut `true`, même écrit `disabled="false"`, comme en HTML.
- Un booléen dit une seule chose. Trois cas ou plus, ou deux booléens qui s'excluent, forment une énumération.

### Énumérations

- Une valeur est en anglais, en minuscules, en kebab-case : `primary`, `medium`, `contains`.
- Une valeur copiée de HTML garde son orthographe : `closerequest`, `_self`, `submit`.
- Le type est une union exportée par `<nom>.type.ts`. Une union commune à plusieurs composants vit dans `packages/components/src/types/common.ts` : `ComponentSize`, `SemanticVariant`.
- Un alignement vaut `start`, `center` ou `end`, qui suivent le sens de lecture. Jamais `left` ni `right`.
- Aucun composant n'a d'attribut `dir` : il lit la direction dans le DOM.

## 4. État et valeur

- Un état que l'application lit ou pose est une propriété réactive. Elle a un attribut quand sa valeur est une chaîne, un nombre ou un booléen.
- Changer l'attribut change la propriété, à tout moment, comme sur un élément natif.
- L'attribut reflète la propriété quand le CSS ou l'ARIA le lit (skill `lit-component`).
- Un état s'appelle `open`, `value` ou `checked`. Un autre nom désigne un état sans équivalent parmi eux.
- Une valeur multiple s'appelle `values` : un tableau, propriété seule. `value` en donne la première, comme un `<select multiple>`, et le formulaire reçoit une entrée par valeur.
- `value` est une chaîne. Rien de choisi vaut `""`, comme dans un `<input>`.
- Une valeur formatée suit le format de HTML : `YYYY-MM-DD` pour une date, `HH:mm` pour une heure.
- Un composant n'émet aucun événement à son premier rendu. Une valeur par défaut n'est pas un changement.
- Un composant émet ses événements comme l'élément natif qu'il imite. `input` et `change` suivent un geste de l'utilisateur, jamais une propriété posée par script.
- L'état interne est privé : champs privés (`#nom`), `@state()`, ou fonctions de `src/state/` ([ADR 0010](?path=/docs/documentation-adr-0010-état-contrôleurs-et-mixins--docs)).

## 5. Événements

- Un composant émet l'événement natif quand il existe : `click`, `input`, `change`.
- Sinon, il émet `u-<verbe>` : `u-close`, `u-cancel`, `u-select`. Le verbe reprend l'événement natif du même rôle, comme `close` et `cancel` de `<dialog>`.
- Le préfixe reste `u-` pour toutes les marques. Une application écoute ainsi les mêmes événements avec chaque marque.
- Chaque événement est une classe de `packages/components/src/events/` : `ModalCloseEvent`. Ses données sont des champs `readonly` (`value`, `option`), jamais `detail`.
- Un événement remonte et traverse les shadow roots : `bubbles` et `composed` valent `true`.
- Un événement émis avant une action est annulable : `preventDefault()` empêche l'action. `u-cancel` garde la modale ouverte, `u-select` garde le texte du champ.
- Un événement qui a plusieurs causes porte `reason`, une union exportée. Ses valeurs viennent du tableau suivant.

## 6. Méthodes et commandes

- Une méthode reprend le nom de la méthode native du même rôle : `showModal()`, `close()`, `requestClose()`, `focus()`.
- Une méthode ne masque jamais une méthode de `HTMLElement` : un popup a `show()`, `hide()` et `toggle()`, pas `showPopover()`.
- Une méthode est un verbe. Un état se lit et se pose par sa propriété, jamais par `getX()` ni `setX()`.
- Un composant qui s'ouvre, se ferme ou bascule reçoit des commandes ([ADR 0008](?path=/docs/documentation-adr-0008-commandes-et-modale--docs)).
- Une commande s'écrit `--<verbe>`, comme les commandes natives : `--show-modal`, `--close`.
- Chaque commande a une méthode publique du même nom, en camelCase : `--show-modal` et `showModal()`.

## 7. Formulaires

- Un champ est un contrôle de formulaire (`withFormControl`). Il prend les attributs d'un contrôle natif : `name`, `value`, `disabled`, `required`, `readonly`, `autocomplete`.
- Il expose les membres de validation natifs : `form`, `validity`, `validationMessage`, `willValidate`, `checkValidity()`, `reportValidity()`, `setCustomValidity()`.
- Il suit la réinitialisation du formulaire, la restauration par le navigateur et le `disabled` d'un `<fieldset>` parent (`withFormControl`, `withDisabled`).
- `readonly` agit comme sur un contrôle natif : le champ est focusable et soumis, mais pas validé.
- Un champ d'une ligne soumet son formulaire par Entrée, comme un `<input>`.
- `disabled` agit comme sur un contrôle natif : le champ n'est ni focusable, ni validé, ni soumis.
- L'erreur s'affiche comme `:user-invalid` : après une interaction, ou après une soumission. Le composant l'expose par `:state(user-invalid)`.
- Le socle n'a pas de composant formulaire : un `<form>` natif contient les champs.

## 8. Parts, slots et états CSS

- Une part est en kebab-case. Elle porte le nom de son élément (`button`, `input`, `dialog`) ou de sa fonction (`hint`, `error`).
- Une part qui contient un composant se nomme `<fonction>-<composant>` : `close-button`, `close-icon`.
- Le calque Figma d'une part porte le nom de la part.
- Le slot par défaut reçoit le contenu principal. Un slot nommé est en kebab-case.
- Une fonction qui demande son propre élément est un slot, jamais un booléen : un slot `icon`, pas un attribut `has-icon`.
- Un état que l'application cible en CSS est un état personnalisé : `:state(user-invalid)`. Son nom est un adjectif en kebab-case, celui de la pseudo-classe native quand elle existe.
- Aucun composant n'a d'attribut `data-state`.
- Les tokens d'un composant suivent [Tokens et couches CSS](?path=/docs/documentation-référence-tokens-et-couches-css--docs).

## 9. Textes et noms accessibles

- Un composant n'écrit aucun texte en dur. Chaque texte est un slot, ou une propriété avec une valeur par défaut en anglais.
- `labels` de `designSystem()` traduit ces textes par nom de propriété. Un même texte porte donc le même nom dans chaque composant : `error-label`.
- Le nom accessible vient du contenu, sinon de `label`. Le composant le reporte sur son contrôle, dans son shadow root.
- De préférence, ne demandez pas `aria-label` sur l'hôte : il nomme l'hôte, pas le contrôle du shadow root.

## 10. Extension par les marques

- Un membre `protected` documenté est une API pour les sous-classes d'une marque.
- Renommer ou retirer un élément public est une rupture ([ADR 0015](?path=/docs/documentation-adr-0015-versions-et-contrat-api--docs)).
- Un composant de marque suit ces règles, avec la balise et les tokens de la marque.
