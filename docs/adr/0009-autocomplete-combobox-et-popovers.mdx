# ADR 0009 — Autocomplete, combobox et popovers ancrés

**Statut :** accepté · **Date :** 14 novembre 2026

## Contexte

Une application a besoin d'un champ texte qui propose des valeurs pendant la saisie : une ville, un produit. Le socle n'a aucun popup attaché à un élément. Un select, un multi-select, un date picker, un menu et une infobulle en demandent un aussi.

- `<input list>` et `<datalist>` proposent des valeurs nativement. Leur liste n'est pas stylable, et son filtrage appartient au navigateur.
- Le pattern ARIA est le combobox : le focus reste dans l'input, `aria-activedescendant` désigne l'option active et `aria-controls` désigne le listbox.
- `aria-activedescendant` et `aria-controls` cherchent leur `id` dans l'arbre de l'input ([ADR 0007](?path=/docs/documentation-adr-0007-champs-de-formulaire--docs)).
- `ariaActiveDescendantElement` vise seulement un élément d'un arbre ancêtre. Il existe depuis Chrome et Edge 135, Firefox 136 et Safari 16.4.
- Aucun polyfill ne crée de relation dans l'arbre d'accessibilité : le navigateur le construit seul.
- Au 14 novembre 2026, le Popover API existe depuis Chrome et Edge 114, Firefox 125 et Safari 17.
- Au 14 novembre 2026, CSS anchor positioning (`position-area`, `position-try-fallbacks`) existe depuis Chrome et Edge 129, Firefox 147 et Safari 26.
- La [matrice](?path=/docs/documentation-référence-support-navigateurs--docs) exige Chrome 111, Firefox 115 et Safari 16.4.

### Critères de décision

1. Le combobox est accessible dans toute la matrice : nom, liste contrôlée, option active.
2. Une application donne les suggestions en HTML ou en données, d'un serveur par exemple.
3. Un composant ne modifie pas les enfants que le framework de l'application gère ([ADR 0007](?path=/docs/documentation-adr-0007-champs-de-formulaire--docs), critère 4).
4. Le popup reste sous son champ et au-dessus de la page, dans toute la matrice.
5. Une application ne télécharge que ce que ses navigateurs demandent.
6. Les futurs composants à popup reprennent les mêmes briques.

## D1 — Les sources des options

- **Option A — Une propriété `options` seule :** des données. Une page HTML sans script ne donne pas de suggestions : le critère 2 échoue en partie.
- **Option B — Des enfants `<option>` du light DOM, désignés tels quels :** `aria-activedescendant` ne les atteint pas avant Chrome 135 et Firefox 136. Le critère 1 échoue.
- **Option C — L'input dans le light DOM, comme Vaadin :** le composant crée un enfant que le framework ne connaît pas. Le critère 3 échoue.
- **Option D — La propriété `options` et les enfants `<option>`, lus comme données :** la liste rend ses propres copies, dans le shadow root de l'input. C'est le choix de Spectrum.

**Décision : D.**

- `options` est prioritaire. Sans elle, les options sont les enfants `<option>` de l'hôte : leur `value`, leur `label` ou leur texte, et `disabled`.
- Le composant lit ces enfants par un `<slot hidden>` et un `MutationObserver`. Il ne les modifie jamais.
- `<option>` est l'élément natif : aucun composant `option` à enregistrer.
- Une option choisie revient dans `u-select`, avec les champs propres à l'application.

## D2 — Le popup et son placement

- **Option A — `popover="auto"` :** un clic dans l'input, hors du popover, le ferme. L'ouverture ferme aussi les autres popovers `auto` de la page.
- **Option B — `popover="manual"` et CSS anchor positioning seul :** sans ancrage CSS, le popover reste au centre du viewport. Le critère 4 échoue dans Firefox avant 147 et Safari avant 26.
- **Option C — `@oddbird/css-anchor-positioning` :** ce polyfill ne gère pas `position-area` avec `position-try-fallbacks`.
- **Option D — `popover="manual"`, CSS anchor positioning, et Floating UI chargé à la demande là où l'ancrage manque.**

**Décision : D.**

- Le composant décide de la fermeture : Escape, le focus qui quitte le champ, un choix.
- Escape ferme seulement le popup. Son `keydown` annulé laisse ouverte une `u-modal` autour du champ.
- `@floating-ui/dom` est une dépendance de `@unicorne/components`, hors du build. Le bundler de l'application en fait un chunk, comme `invokers-polyfill` ([ADR 0008](?path=/docs/documentation-adr-0008-commandes-et-modale--docs), D2).
- Le premier composant connecté charge Floating UI, là où l'ancrage manque. Le popup s'affiche une fois positionné.
- Un popover fermé est masqué par `display: none !important`. Ni un `display` du composant ni un `::part()` de marque ne l'affichent.

- Un comportement de plusieurs familles est un mixin. Le comportement d'une famille est une base abstraite, comme `FieldBase` et `ButtonBase`.
- `ComboboxBase` étend `FieldBase` : un combobox a le libellé, l'indice, l'erreur et le comportement de formulaire d'un champ.
- Le contenu du popup reste libre : une liste d'options pour `withListbox`, une grille pour un date picker.
- Les tokens suivent le même découpage : le groupe `combobox` pour le popup, le groupe `listbox` pour les options.

## D4 — La valeur de l'autocomplete

- La valeur est le texte de l'input, libre, comme avec `<input list>`. Une suggestion choisie remplit la valeur.
- Le choix envoie `u-select` (`ListboxSelectEvent`), annulable, puis `input` et `change`, comme une saisie.
- `filter` choisit les suggestions affichées : `contains` (par défaut), `starts-with`, ou `none` quand l'application filtre elle-même.
- La comparaison ignore la casse et les accents : « evry » trouve « Évry ».
- Les suggestions du navigateur (`autocomplete`) sont désactivées par défaut : elles couvriraient la liste.

## Conséquences

- **Code :**
  - `withAnchoredPopover` et `withListbox`, dans `packages/components/src/mixins/` ;
  - `packages/components/src/polyfills/anchor-positioning.ts` ;
  - `ComboboxBase` (`src/components/combobox/`), `Autocomplete` (`src/components/autocomplete/`) et `ListboxSelectEvent` (`src/events/listbox-select.ts`).
- **API :**
  - `u-autocomplete` rejoint le catalogue ; ACME le propose.
  - Le `<label>` de `FieldBase` reçoit `id="label"`, qui nomme le listbox.
  - L'événement `u-select` porte l'option choisie dans `option`.
- **Tokens :**
  - les groupes `combobox` et `listbox` ;
  - les tokens sémantiques `size.popup` et `z-index.overlay` ;
  - les primitives `dimension.6400` et `z-index.1000`.
- **Dépendance :** `@floating-ui/dom` (MIT).
- **Tests :**
  - les stories de `autocomplete` dans les trois moteurs ;
  - les tests des deux mixins ;
  - `src/polyfills/anchor-positioning.test.ts`, sans Popover API ni ancrage CSS ;
  - `src/components/autocomplete/autocomplete.test.ts`, qui presse le vrai Escape dans une modale ;
  - le test d'ACME et celui de l'application Vue `examples/acme-vue-app`.
- **Limites :**
  - Avant Chrome 114, Firefox 125 et Safari 17, un ancêtre qui coupe son débordement coupe le popup : le `<dialog>` de `u-modal`, par exemple.
  - L'analyseur du manifest lit `@tokens` sur une classe, pas sur un mixin. Un composant qui applique `withListbox` écrit `@tokens listbox`.
- **Documentation :** cet ADR, la référence [Mixins](?path=/docs/documentation-référence-mixins--docs), la matrice, `AGENTS.md` et les skills `lit-mixin` et `lit-component`.

## Questions ouvertes

- **Annonces :** une live region pour le nombre de suggestions, l'absence de résultat et le chargement, comme `wa-combobox`.
- **Suggestions asynchrones :** un état `loading`, un anti-rebond, une fonction `dataSource` avec un `AbortSignal`.
- **Affichage :** la mise en évidence du texte trouvé, l'autocomplétion dans l'input, les `<optgroup>`.
- **Valeur imposée :** un `select` et un `combobox` sur `ComboboxBase`, dont la valeur est une option. Le `<select>` personnalisable (`appearance: base-select`) les remplace une fois dans toute la matrice.
- **Reference Target dans toute la matrice :** des options du light DOM deviennent possibles sans copie.
- **Soumission implicite :** Enter dans un champ du socle n'envoie pas le formulaire, car l'input interne n'a pas de formulaire. La question concerne `FieldBase`.
