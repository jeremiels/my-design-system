# Support navigateurs

Le socle supporte les canaux étendus des entreprises (Firefox ESR, Chrome et Edge Extended Stable). Il supporte aussi Android et iOS, y compris le Safari des iPhone bloqués sur iOS 16.

- **Source de vérité :** le champ `"browserslist"` de `package.json`. Il alimente `build.target` (JS), `build.cssTarget` (CSS, abaissé par Lightning CSS) et `npm run compat`.
- **Noms Android :** dans `browserslist`, `chrome` et `firefox` désignent les versions de bureau. Android a ses propres noms : `and_chr`, `and_ff`, `samsung` et `op_mob`.
- **Une version récente seulement :** les données de `browserslist` ne connaissent qu'une version récente de `and_chr`, `and_ff` et `op_mob`. Le plancher de leur moteur est vérifié par `chrome >= 111` et `firefox >= 113`.
- **Plancher :** pour chaque moteur, la première version qui a toutes les fonctionnalités du code. La dernière colonne nomme la fonctionnalité qui le fixe.
- **Versions figées :** la matrice nomme des versions, pas une requête glissante comme `baseline widely available`. Elle change seulement par une décision.
- **Windows 7 et 8.1 :** la matrice ne les vise pas. Chrome 109, leur dernier Chrome, est sous le plancher.

## Fonctionnalités à surveiller

<table>
  <thead>
    <tr>
      <th>Fonctionnalité</th>
      <th>Règle</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>Nesting CSS</td>
      <td>
        Autorisé dans les sources : Lightning CSS l'aplatit au build. Le serveur de développement ne
        l'abaisse pas.
      </td>
    </tr>
    <tr>
      <td>CSS module scripts</td>
      <td>
        Jamais livrés : le plugin `plugins/css-import-attributes.ts` les compile. Le build échoue
        s'il reste un import `.css` dans le JS produit.
      </td>
    </tr>
    <tr>
      <td>`:state()`</td>
      <td>
        Amélioration progressive : `customStates` est sans effet sur Chrome 90–124, Firefox avant
        126 et Safari avant 17.4. Un état nécessaire au rendu se reflète aussi en attribut.
      </td>
    </tr>
    <tr>
      <td>`::backdrop`</td>
      <td>
        N'hérite de rien avant Chrome 122, Firefox 120 et Safari 17.4. Une valeur de repli littérale
        y est tolérée.
      </td>
    </tr>
    <tr>
      <td>`text-wrap`, `interpolate-size`</td>
      <td>Amélioration progressive, `interpolate-size` sous `@supports`</td>
    </tr>
    <tr>
      <td>`color-mix(in oklch, …)`</td>
      <td>
        Écart accepté : Chrome 113 et Firefox 115 décalent un peu les couleurs de survol vers le
        violet
      </td>
    </tr>
  </tbody>
</table>

Toute autre fonctionnalité récente se vérifie contre la matrice (MDN, caniuse) avant usage.

## Vérifications

<table>
  <thead>
    <tr>
      <th>Commande</th>
      <th>Ce qu'elle vérifie</th>
    </tr>
  </thead>
  <tbody>
    <tr>
      <td>`npm run compat`</td>
      <td>
        Syntaxe JS de `dist/` (`es-check`) et fonctionnalités CSS des sources (`doiuse`), contre la
        matrice
      </td>
    </tr>
    <tr>
      <td>`npx vitest run`</td>
      <td>
        Stories et tests, dans les versions récentes de Chromium, Firefox et WebKit (Playwright)
      </td>
    </tr>
    <tr>
      <td>`npm run example`</td>
      <td>Le `dist/` livré, consommé par la marque ACME, dans une version récente de Chromium</td>
    </tr>
  </tbody>
</table>

- `doiuse` ne connaît que les données de caniuse. Il ne détecte ni `color-mix()`, ni `text-wrap`, ni l'héritage de `::backdrop`, ni `:state()`, ni les at-rules imbriquées.
- Les constats de `doiuse` acceptés sont listés avec leur raison dans `IGNORED` (`scripts/check-css-compat.mjs`).
- Aucun test automatique ne couvre les versions minimales : Vitest et `npm run example` utilisent les navigateurs récents de Playwright. Seul `npm run compat` vérifie la matrice.
- Aucun test automatique ne tourne sur Android : Vitest teste Chromium et Firefox dans leurs versions de bureau. Samsung Internet n'est testé nulle part.
