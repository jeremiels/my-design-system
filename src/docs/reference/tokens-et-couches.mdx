- Les styles de l'application hors couche l'emportent sur toutes les couches du socle.
- Les styles internes des composants vivent dans leur shadow DOM. Les couches de la page ne les atteignent pas.
- `src/styles/layers/tokens.css` importe un fichier par sous-couche, puis déclare leur ordre : `u.tokens.color`, `u.tokens.semantic`, `u.tokens.spacing`, `u.tokens.typography`, `u.tokens.radius`, `u.tokens.motion`, `u.tokens.elevation`.
- Une marque ajoute ses valeurs dans la sous-couche `u.tokens.brand`, importée après celles du socle.

- Chaque niveau référence le niveau précédent. Seules les primitives contiennent des valeurs littérales.
- Les états de survol et d'appui (`-hover`, `-active`) mélangent la couleur de l'intention avec `--u-color-text`, par `color-mix()`.
- Les tokens sémantiques sont déclarés sur `:root` et sur `[data-brand]`.

## Tokens de composant

- Chaque token de composant est déclaré sur `:host`. Sa valeur par défaut est un token sémantique, jamais une primitive ni une valeur littérale.
- Nom : `--u-<composant>-<propriété-css>[-<état>]`, par exemple `--u-button-background-color-hover`.
  - `<composant>` est le nom du composant sans préfixe : `button`, pour `u-button` comme pour `acme-button`.
  - `<propriété-css>` est le nom complet de la propriété : `background-color`, pas `bg`.
- Chaque token déclaré sur `:host` est documenté dans la JSDoc de la classe : `@cssprop [--u-button-padding-inline=var(--u-spacing-md)] - description`.
- Une variante ou une taille change les valeurs par défaut sur l'hôte, à partir de l'attribut reflété : `:host([variant="danger"])`, `:host([size="small"])`.
- Aucune règle d'un élément interne ne redéclare un token documenté.
- Les règles internes lisent les tokens : `background-color: var(--u-button-background-color)`.

`src/api-contract.test.ts` vérifie ces règles. Les tokens documentés sont exactement ceux déclarés sur `:host`. Aucun n'est redéclaré ailleurs. Un token posé sur l'hôte s'applique dans chaque état `:host([…])`.

## Valeurs de repli

Un `var()` n'a pas de valeur de repli littérale : la feuille de tokens est une dépendance des composants. Deux exceptions :

- Les mots-clés système de `forced-colors` (`ButtonText`, `Highlight`, `CanvasText`) dans les media queries d'accessibilité.
- `::backdrop` dans `modal.css` : avant Chrome 122, Firefox 120 et Safari 17.4, il n'hérite d'aucune custom property.

## Mouvement réduit

`src/styles/tokens/motion.css` met `--u-motion-duration-*` à `0ms` sous `@media (prefers-reduced-motion: reduce)`. Les composants lisent ces tokens et n'ont pas leur propre media query.

## Feuille d'un composant

Les styles d'un composant ou d'un mixin vivent dans un fichier `.css` voisin, importé comme CSS module script :

```ts
import alertStyles from "./alert.css" with { type: "css" };

static styles = [DSBaseElement.styles ?? [], alertStyles];
```

- L'import donne un `CSSStyleSheet` constructible, que Lit adopte.
- Le plugin `plugins/css-import-attributes.ts` compile cet import pour Vite, Storybook, Vitest et le build.
- Les classes internes (`.button`) ne sont pas une API. Une marque style les éléments internes par leurs parts : `[part~="button"]`.
