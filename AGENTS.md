# Agent Instructions — My Design System

A **white-label base** for design systems: Lit web components (`button`, `button-link`, `alert`, `modal`), `--u-` design tokens and the tooling to extend them. Each brand design system depends on this package, extends it, registers it under its own tag prefix and republishes it ([ADR 0001](src/docs/adr/0001-architecture-multi-marque.mdx)). Nothing is published yet: breaking changes are still cheap.

Stack: Lit 3 (peer dependency, never bundled) · Vite 8 · strict TypeScript with Lit's legacy decorators · Vitest + Storybook 10 + Playwright · oxlint/oxfmt · Node ≥ 24.8, npm ≥ 11.6.

This file is an index. The details live in the docs and in the project skills (`.claude/skills/`): load the skill that matches the task before starting it.

## Where things are

- `src/components/<name>/` — class, sibling `.css`, `.type.ts`, `.stories.ts`; `base-element.ts` (`DSBaseElement`: shadow DOM defaults, registration contract, `tagFor()`).
- `src/mixins/` — `withDisabled`, `withInternals` ([docs](src/docs/mixins/)).
- `src/events/` — one typed `Event` class per custom event (`modal-close.ts`).
- `src/registry/` — `defineComponents()` and the catalog (`allComponents`); `src/define.ts` registers it under `u-`; `src/index.ts` is side-effect free.
- `src/styles/` — document-level CSS: `main.css` (→ `styles.css`, tokens + utilities), `reset.css` (→ opt-in `reset.css`), `layers/`, `tokens/`.
- `custom-elements.json` — the public API, generated by `npm run analyze` and **committed**.
- `plugins/css-import-attributes.ts` — the Vite plugin behind `import sheet from "./x.css" with { type: "css" }` (exit strategy in its header).
- `examples/acme-design-system/` — an example brand design system, built and tested against the packed base.
- `tests/legacy/` — smoke test of `dist/` in a real Firefox ESR 115.
- `.changeset/` — pending release notes; `.github/workflows/ci.yml` — CI.

## Rules for every change

- **Registration (ADR D1–D2):** a component never registers itself; it sets `static componentName` and joins `allComponents`. To render another component: `static dependencies` + `this.tagFor()`, never a hard-coded tag nor `document.createElement`.
- **Public API (D3, D5):** only what the JSDoc documents (`@slot`, `@csspart`, `@cssprop`, `@fires`, documented `protected` members); the rest is `private`/`#private`/`@internal`. After an API change: `npm run analyze`, read the `custom-elements.json` diff, commit it.
- **Styles:** a sibling `.css` file imported `with { type: "css" }`, never Lit's `css`. Tokens: `--u-` prefix, primitive → semantic → component, no literal values. Global layers all live under `u` (`u.reset` … `u.shame`). Brands style the base's internals through its parts (`[part~="button"]`), never its classes.
- **Browsers:** the matrix is pinned in `package.json` (Chrome/Edge 111, Firefox 115 ESR, Safari 16.4): check any recent CSS/JS feature against it first.
- **Accessibility:** native elements first; stories fail on any axe violation; default tokens keep WCAG AA contrast (`src/styles/tokens.test.ts`).
- **Release notes:** every change to what the package ships comes with a changeset (`npm run changeset`); a breaking change to the public API is `major`.
- **Lit imports:** any new `lit/...` module goes in `optimizeDeps.include` (`vite.config.ts`).

## Commands

```sh
npm run dev | storybook          # Vite demo (index.html) | Storybook on :6006
npm run build                    # manifest, ES modules, .d.ts, plugin → dist/
npm run check                    # oxlint, oxfmt --check, tsc, api:check, Vitest — what CI gates on
npx vitest run --project browser # one Vitest project: unit (Node), browser (Chromium), storybook (3 engines)
npm run example                  # packed base → ACME install, build, smoke test (after package changes)
npm run compat                   # es-check + doiuse against the browser matrix
npm run test:legacy              # dist/ in a real Firefox ESR 115
npm run lint | fmt               # auto-fix
npm run changeset                # describe a change for the changelog
```

`api:check` compares the regenerated manifest with the one in the git index: stage `custom-elements.json` before running `check` locally.

CI (`.github/workflows/ci.yml`, pushes to `master` and pull requests) runs `check`, then `example`, `compat` and `test:legacy`.
